# Phase 5.5 audit: model improvements, statistical validation and production readiness

Generated by `python -m src.modeling.phase5_5_report`. Everything here ran on local data. No API calls, no scraping, no purchases, nothing committed or pushed.

## Bottom line

* **Existing models are unchanged and reproducible.** All Phase-1 to Phase-5 model files hash exactly as they did at the start of this phase (verified). New work lives in new versions: `qb_career_production v1.1.0` and `qb_draft v1.1.0`.
* **The draft-probability population is a heuristic, now audited.** 538 FBS passer-seasons stay `eligibility_unknown`. The model is not extended to them.
* **The Combine gain is almost all participation.** College-only AUC 0.878; + participation flag 0.906; + measurements 0.907; measurements without the flag 0.871.
* **The round model survives nested validation.** 7-round RPS 0.176 vs 0.208 for historical frequencies; three groups 0.176 vs 0.225. Pick median miss 47 vs 81, but 80% pick intervals cover only 75%.
* **Fair production accuracy is modest.** With model choice inside the folds, average MAE skill vs the historical median is +1.6% pre-draft and +26.0% post-draft (games started MAE 20.1 / 14.1 vs median 20.6).
* **Intervals.** The shipped v1.1.0 80% intervals cover 79% (pre-draft) and 77% (post-draft) in the nested backtest, against 78% / 73% for the Phase-5 method. Rushing remains under-covered.
* **Start probabilities are nested** (Phase-5 logits crossed for 16 / 27 of 107 test QBs). 64+ starts pre-draft is poorly calibrated (slope 0.24) and flagged.
* **Git-safe artifacts.** The v1.0.0 production files embed 183 QBs' career lines and residuals. They stay on disk unchanged but are now gitignored. v1.1.0 holds parameters only; its reference tables are a gitignored, hash-pinned data file. The simulation reproduces v1.0.0 exactly.
* **A unified, tested forecast interface** (`prediction_api.forecast_prospect`) and a labelled historical-backtest interface (`historical_backtest.historical_backtest`) are ready for an API layer.

## 5. Remaining limitations

* Draft eligibility, declarations and transfers are inferred, not observed (see `draft_eligibility_audit.md` for the sources that would close the gap).
* About 10 QBs per draft class and ten test classes: every metric has wide class-bootstrap intervals.
* 64+ starts (few events) and rushing totals (drift toward mobile QBs) are the least reliable outputs.
* The pooled selection rule was designed after seeing the per-target rule fail. Its nested numbers are slightly optimistic.
* Pick intervals under-cover (80% nominal, about 75% measured).
* Comparisons are explanatory. Their neighbours shift when single features are dropped.
* Post-Combine draft probability encodes the NFL's invitation decision.

## 7. Recommended next steps

1. **Dashboard (next phase).** Build on `prediction_api` and `historical_backtest` with the display rules in `frontend_readiness.md`; start with a FastAPI wrapper around `forecast_prospect`.
2. **Declaration and portal data (needs approval).** The NFL early-entrant list and CFBD `/player/portal` + `/roster` would replace the eligibility heuristic and allow underclassman draft probabilities.
3. **2026 class as a prospective test.** Freeze today's forecasts (hash them) and score them as seasons are played.
4. **More classes before more complexity.** Most limits here are sample size. The 2022-2024 classes complete their five-season windows in 2026-2028 and should be added before new model families are tried.
5. **Passer-level 2004-2015 play-by-play** after the CFBD quota reset (about 200 calls, needs approval).
